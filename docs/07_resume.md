# 07 · 简历项目描述 + 写作范本

> 本文给出**可直接贴进简历的项目描述**，以及**通用写作范本**，供你套用到其他项目。

## 1. 简历项目描述（可直接用）

> **PE-Agent · 系统救援 Agent**（2026.11–2027.01，个人开源）
>
> 基于麒麟桌面系统修复场景，用 **LangGraph + RAG + Skill 框架 + FastAPI** 构建 LLM 驱动的系统运维 Agent：
> - 将「分级故障诊断状态机」重构为 **LLM 决策循环**（观察→规划→执行→反思→迭代），封装挂载/引导修复/日志分析等 8 类原子工具与 2 个 SOP 技能，支持技能动态注册/启停/安全扫描；
> - 自建**故障注入评测集**（对齐 ClawEval），以「完成度/安全性/鲁棒性」三维度量化，结合 Reflexion 反思入记忆实现失败轨迹自进化闭环；
> - 落地**运行时安全管控**（提示注入拦截 / 危险命令过滤 / 挂载白名单 / 全链路审计，对齐腾讯朱雀 A.I.G 风险分类），保障高危操作零误伤；
> - 预留 Java(Spring Boot) 后端壳，覆盖 Agent 开发与后端两条技术线。

**精简一版（三行，适合窄栏）：**

> **PE-Agent 系统救援 Agent**（LangGraph + RAG + FastAPI）：将麒麟系统修复状态机重构为 LLM 决策循环，封装 8 类工具 + Skill 框架；自建故障注入评测集，三维度量化修复成功率，Reflexion 反思实现自进化；落地提示注入/危险命令/挂载白名单三重安全管控。

## 2. 写作范本（通用方法论，可套用）

### 2.1 结构公式

```
[项目名 + 一句话定位]（时间 + 性质）
基于 [业务场景]，用 [技术栈] 构建 [产品/系统]：
- [做了什么 · 动词开头 · 含技术名词]
- [做了什么 · 动词开头 · 含量化结果]
- [做了什么 · 动词开头 · 含难点/差异化]
```

### 2.2 三个硬规则

1. **动词开头**：`重构 / 封装 / 自建 / 落地 / 设计 / 实现`，不要「负责」「参与」「协助」。
2. **量化结果**：修复成功率 X%→Y%、平均步数降低 Z%、覆盖率、QPS、延迟——没有数字就写「可量化的维度」。
3. **技术名词打点**：LangGraph / RAG / MCP / Reflexion / 向量检索 / 安全护栏……面试官扫一眼就知道你在哪个赛道。

### 2.3 一鱼两吃：Agent 岗 vs 后端岗

| 岗位 | 侧重改写 |
|---|---|
| **Agent 岗** | 强调 Agent Loop、RAG、Reflection、Evaluation、Security |
| **后端岗** | 强调 FastAPI 服务、接口设计、Pydantic 校验、Java/Spring Boot 壳、并发/稳定性 |

> 同一个项目，投 Agent 岗突出「决策闭环 + 评测 + 反思」，投后端岗突出「服务层 + 工程化 + 接口设计」。

### 2.4 反例 → 正例

| 反例（空洞） | 正例（具体） |
|---|---|
| 负责开发了一个 AI Agent | 用 LangGraph 将分级故障诊断状态机重构为 LLM 决策循环（观察→规划→执行→反思→迭代） |
| 做了评测 | 自建故障注入评测集，按完成度/安全性/鲁棒性三维度量化修复成功率 |
| 加了安全功能 | 落地提示注入拦截 + 危险命令过滤 + 挂载白名单三重运行时护栏 |

## 3. 面试如何讲这个项目（STAR）

- **S（背景）**：麒麟实习做了系统修复工具，是规则状态机；想把它 Agent 化展示完整 AI 能力。
- **T（任务）**：把硬编码 if-else 换成 LLM 决策，加反思迭代，并配套评测和安全。
- **A（行动）**：LangGraph 四节点闭环 + RAG 案例检索 + Skill 框架 + Reflexion 反思 + 三维度故障注入评测 + 三道闸安全管控。
- **R（结果）**：跑通端到端闭环，评测可量化，安全零误伤，可讲清楚每个组件原理。
